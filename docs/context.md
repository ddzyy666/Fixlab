# 请求上下文构建与压缩

新增 `fixlab/context.py`，采用确定性规则，不调用摘要模型。默认关闭，启用示例：

```powershell
python -m fixlab evaluate .fixlab/real-tasks --task-id more-itertools-658 --backend docker --context-max-tokens 16000 --max-tokens 200000 --max-steps 30
```

run、evaluate、compare、resume、resume-batch 均支持此参数。它保存在任务预算配置中，续跑默认继承。已完成的任务不会因设置此参数重新调用模型。

## 数据与请求分离

SQLite 保存原始消息和工具结果。每次请求仅构建一个副本：未超限时保持消息内容；超限时保留全部 system/user 消息、最近一次完整交互和预算内的近期连续交互，并添加结构化历史摘要。工具调用及其所有结果必须完整配对；待执行工具先由原运行循环完成，构建器拒绝向模型发送未配对的历史。

摘要包含成功修改的文件路径、最近测试/自检结果、近期工具操作及简短错误。早期读取代码、搜索输出不再重复携带，模型需要时重新读取。摘要明确标注为不可信任务数据，不提升为系统指令。保留所有 user 消息是保守选择，包含很长的验收反馈时可能需要更大预算。

## 测试结果的新鲜度

在 run_tests/self_check 前后计算工作副本快照 SHA-256；只有前后一致且与当前快照一致，摘要才标为当前有效。指纹范围与原有快照规则一致。旧记录没有指纹，或文件改变时，摘要标为 unknown_or_stale。它只证明文件快照一致，不保证外部环境未变化，也不替代最终独立验收。

## 预算和可审计性

--context-max-tokens 使用 UTF-8 序列化字节数 / 3 加消息开销的启发式估算，同时包含工具定义，并预留 2048 Token 输出空间。不是模型 tokenizer，也不会设置供应商输出长度参数；无法保证严格不超过供应商窗口。--max-tokens 仍是任务累计已报告用量限制，两者独立。

必要消息、最新完整工具交互及摘要仍放不下时，停止为 budget_exhausted，原因 context_limit，不静默截断任务或工具参数。提高上下文上限后可续跑。它目前不做向量检索、模型摘要或自动拆分单个过大的工具结果。

context_build 事件记录策略版本、估算前后大小、保留/删除的消息索引区间（从 0 开始，右端不含），便于核对。压缩不修改原 SQLite 历史。每次从完整记录重建，因此续跑不依赖临时内存摘要。

## 离线验证

对 more-itertools 已完成案例最后一次请求前的历史离线重建：包含当前工具定义和收尾提示，估算输入由 23078 减至 12166，约减少 47%。记录在本地 .fixlab/context-validation.json；未调用付费模型。此结果不是实际计费节省，也不能证明压缩后修复成功率不变，正式效果需要新的对照运行。
